# `mavor` Documentation

Four trees, and the difference between them is what a reader is allowed to
believe.

| Tree | Holds | Trust it for |
| :--- | :--- | :--- |
| [Guides](#guides) | Task-oriented instructions | What to do, right now |
| [`reference/`](#reference) | How the built system works | What the code actually does |
| [`reports/`](#reports) | Generated measurements | Numbers, on the machine named in the header |
| [`design/`](#design-proposals) and [`planning/`](#planning) | Proposals and stories | What is being *considered*, never what exists |
| [`research/`](#research) | The world outside this repo | Libraries, protocols, prior art |

> [!IMPORTANT]
> A document under `design/` or `planning/` describes intent. If it disagrees
> with the code, the code is right and the document is a proposal that has not
> landed — check [`../roadmap.md`](roadmap.md) before treating either as a bug.

## Guides

- [**Quickstart**](quickstart.md) — install, `mavor setup`, bind a key, dictate.
  Five steps, and what to check when one does not land.
- [**User Guide**](user-guide.md) — the same territory in depth: engines,
  streaming, ducking, systemd, every config key.
- [**Choosing a Model**](choosing-a-model.md) — which of the catalogued models
  to actually use, decided from the measurements rather than from reputation.

## Reference

- [**How mavor works**](reference/how-mavor-works.md) — the daemon as built:
  the state machine, the side-effect listener, the five interfaces, the failure
  paths, and the invariants a maintainer breaks by accident. Carries a
  verification date and the commit it was checked against.

## Reports

Generated by the harness — rerun rather than edit.

- [**Measured Model Benchmarks**](reports/model-benchmarks.md) — speed, memory
  and accuracy for every installed model on every backend this machine can run,
  plus thread scaling and warm-server-versus-cold-CLI. Regenerate with
  `just bench`; the raw results are in `reports/benchmarks/latest.json`.

## Design proposals

Unbuilt. Each says so at the top.

- [**Active window context and vocabulary prompting**](design/active-window-context-and-vocabulary-prompting.md)
  — biasing recognition with what is on screen. In review.
- [**Next-generation edge runtimes**](design/next-gen-runtimes-executorch-iree.md)
  — ExecuTorch and IREE against the graph interpreters mavor uses. Frozen, and
  nothing in it has been measured.

## Planning

- [**Dictation workflows**](planning/dictation-workflows.md) — narrative user
  stories walking five people from discovery to daily use. Its inline **Gap:**
  notes name what is *missing*, which is the point of the document.

## Research

Evergreen notes on the world outside this repo.

- [**Wayland dictation stack**](research/wayland-dictation-stack.md) — input
  protocols, PipeWire capture, hotkey models, and the OSS field.
- [**Open-weight models and runtimes**](research/open-weight-models-and-runtimes.md)
  — the ASR model and inference-runtime landscape.
- [**Hosted STT and post-processing**](research/hosted-stt-and-postprocessing.md)
  — cloud APIs and LLM cleanup passes. Deprecated: mavor is local-only, and
  this is kept for the architectural comparison, not as an option.
